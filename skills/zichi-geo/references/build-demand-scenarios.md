# build-demand-scenarios — 建立客户问题与购买场景库

> 状态：OpenSpec 已规划，尚未实现。不得用旧 brand/search/qa/intent 四桶代替正式场景库。

## 目标

把“谁在什么情况下、需要解决什么、会怎样问、企业凭什么回答”整理成平台无关的业务场景。一个场景是可复用的策略对象，不是一篇文章模板。

## 前置条件

- 已确认 `fact_snapshot_id`
- 已确认 baseline diagnosis run/report
- 原始词表、询盘和运营输入只能作为可追溯候选来源

## 每个场景的业务字段

1. 场景名称
2. 目标客户
3. 客户需求
4. 关注条件或约束
5. 代表性 AI 问题（可多条）
6. 支持回答的已确认事实/证据，或明确的 evidence gap
7. 可选的期望下一步行动

这些字段用于描述客户决策情境，不要求全部写进同一篇文章。

## 计划流程

1. 汇总事实快照、诊断 gaps、客户原始词表、询盘和运营输入。
2. 生成场景候选与问题 facets；保留地区、决策阶段、正负面、产品/能力等独立维度。
3. 精确去重，再提出语义合并建议；有业务差异的家庭/商用、零售/OEM、全国/地区场景不得误合并。
4. 按业务价值、诊断缺口、证据就绪度、客户原话和运营判断给出可解释优先级。
5. 输出业务可读预览，逐项批准、编辑、拒绝或延期，最终确认 scenario library version。

## 闸门

未确认场景库不得进入内容规划。高优先级 evidence gap 必须解决、延期或明确接受，禁止补造事实。
